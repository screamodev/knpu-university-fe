# Пошук по сайту

Один пошук на всі три місця, де живе текст сайту. Точка входу — кнопка в шапці (і ⌘K / Ctrl+K),
повні результати — `/search?q=…`.

## Чому не одне джерело

| Звідки текст | Обсяг | Коли змінюється |
|---|---|---|
| Directus — 25 колекцій | ~2 200 рядків, ~3 МБ | щодня |
| `app/content/**` — 15 текстових сторінок + 64 вкладки факультетів | 995 тис. символів у 116 секціях | при деплої |
| `app/locales/{uk,en}.json` — копія 135 шаблонних сторінок, підписи меню, 193 назви підрозділів у `app/utils/structure.ts` | 187 КБ | при деплої |

Пошук лише по Directus не знайшов би ні «гуртожиток», ні «стипендія»: сторінки, які це пояснюють,
зібрані з ключів локалізації.

## Як влаштовано

```
build ──→ scripts/build-search-index.mjs ──→ server/assets/search-static.json
                                                      │
runtime ─→ server/utils/search/directus.ts ──→ [ MiniSearch ] ──→ /api/search
              (кеш 10 хв)                                │
                                            SearchOverlay   /search
```

- **Статична половина** збирається під час білду (`pnpm build` запускає скрипт першим). Дев-контейнер
  збирає її у `docker/entrypoint-dev.sh`. Файл не комітиться — він генерується.
- **Динамічна половина** тягнеться з Directus при першому запиті й оновлюється раз на 10 хвилин.
  Колекція, яка впала, пропускається з попередженням у лог — решта пошуку працює.
- **Індекс** будується лениво, при першому запиті. Поки будується новий, старий продовжує відповідати.

| Файл | Що робить |
|---|---|
| `scripts/build-search-index.mjs` | локалі + `content/**` + оргструктура → статичний індекс |
| `app/utils/searchRoutes.ts` | простір імен локалі → маршрут (`education.digitalCenter` → `/education/digital-center`) |
| `server/utils/search/collections.ts` | **єдине місце**, де описані колекції Directus |
| `server/utils/search/directus.ts` | вибірка з Directus, кеш, розбиття на фрагменти |
| `server/utils/search/text.ts` | очищення HTML, фрагменти, нормалізація термів — спільна для обох половин |
| `server/utils/search/engine.ts` | MiniSearch, дедуплікація за URL, підсвітка |
| `server/api/search.get.ts` | `?q=&type=&locale=&limit=&offset=` |

## Українська морфологія

Стемера української немає в жодному з доступних варіантів (у Postgres теж — там 29 конфігурацій,
української серед них немає). Замість нього:

- **пошук за префіксом** — `студент` знаходить «студентів», «студентам», «студентський». Це і є
  стратегія словозміни;
- `fuzzy: 0.2` — «Сковорда» все одно знаходить Сковороду;
- нормалізація апострофів (`'ʼ\``), `ё→е`, стоп-слова uk/en.

## Що робити, коли…

**Додали колекцію в Directus** — один запис у `SEARCH_COLLECTIONS`. Поля запитуються через `*`, тому
неіснуюче поле в описі нічого не ламає (Directus віддає 403 на явний список із зайвим полем — саме
тому там `*`).

**Перейменували сторінку** — якщо на неї вказував `LOCALE_ROUTE_OVERRIDES`, білд впаде з повідомленням,
який ключ куди вказує. Це навмисно: мовчазна втрата сторінки з пошуку гірша за зламаний білд.

**Пошук нічого не знаходить по статичних сторінках** — не зібрався `server/assets/search-static.json`.
`pnpm build:search-index`.

## Межі

- **PDF шукаються за назвою й описом, не за вмістом.** Витягування тексту з ~2 000 файлів (4,89 ГБ) —
  окрема робота; поле під нього в моделі документа вже передбачене.
- **Затримка до 10 хвилин** між публікацією в Directus і появою в пошуку. Прибирається вебхуком
  Directus Flow на `/api/search` з інвалідацією кешу.
- **Пам'ять**: індекс додає ~35 МБ до процесу. Прод-контейнер обмежений `mem_limit: 384m` — запас є,
  але при істотному зростанні контенту це перше, що варто перевірити.
- Якщо корпус переросте in-process індекс, за `/api/search` можна поставити Meilisearch, не чіпаючи UI.
